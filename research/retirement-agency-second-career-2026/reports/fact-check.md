## 3. 比較サイトのみを根拠にしていないことの確認

比較サイト・まとめサイトは**候補の発見にのみ**使用し、以下の判定根拠には使っていない。

- 倒産・解散・サービス終了の判定 → 裁判所情報・TSR・運営企業公式のみ
- 運営法人名・所在地・料金 → 各社の特商法ページを一次情報とした
- 運営形態 → 公式サイトの記述。比較サイトの記述は `operator_type_raw_candidates` に残すのみ

比較サイトの記述と公式の記述が食い違った場合は公式を採り、食い違いを `notes` と
`operator_type_conflict` に記録した。31件で矛盾が発生している。

## 4. 誤りを検出して修正した箇所

調査中に自分の処理の誤りを見つけて直した。再現時に同じ罠を踏まないよう記録する。

| 誤り | 影響 | 修正 |
|---|---|---|
| ドメイン一致でも名寄せしていた | 同一運営会社の別ブランド（`男の退職代行` と `わたしNEXT`、どちらも to-next.jp）が1件に統合され、母集団が過小になっていた | ドメイン統合を廃止し、サービス名の正規化＋監査可能な別名表（`raw/alias_map.csv`）に変更 |
| `service_id` を出現順で採番していた | 名寄せを更新するたび採番が変わり、収集済みファイルとの突合が壊れ、調査済み5社が未調査扱いになっていた | `normalized/service_id_registry.csv` でIDを固定。突合はサービス名で行う |
| LPのサブドメインだけで生存判定していた | `lp.example.jp` が消えただけで本体が生きているサービスを「消滅」と誤計上する危険があった | 名前解決失敗時に本体ドメインへ1回フォールバック。該当10件はフォールバックしても復活せず |
| アーカイブ照会を深い階層のURLで実行 | スナップショットなしが多発し、過去との比較ができなかった | サイトルート基準に変更し、取得件数が2024年18→35件に改善 |
| Wayback availability API の回答を信用 | 連続実行で結果が変動（2024年分 19→15→18→26件）し、`status_2024` が不安定だった | APIの有無ではなく「実際に取得して読めたか」で判定 |
| 価格帯別の継続率を2026年価格で算出 | 全価格帯が継続率100%、UNKNOWNのみ52.6%という生存バイアスの産物を出していた | アーカイブから最終観測価格を復元。それでも交絡が残るためH2は検証不能と判定 |
| 運営形態別の継続率を発見として扱いかけた | 民間100%・弁護士100%・労働組合100%という算術上の帰結を結論にする寸前だった | 全行に警告列を付し、H3を検証不能と明記 |
| findings.md の訴求件数の分母を取り違え | 支援項目の件数と分母が実データと不一致だった | `analysis/second_new_grad_support.csv` と照合して全数値を修正 |

## 6. 反証の方法

本調査の結論を覆したい場合、次のいずれかを示せばよい。

1. **「第二新卒」を訴求している退職代行サービスの公式サイト**を1件でも示す → 中心的な事実が崩れる
2. **2024-01-01〜2026-10-07に倒産・解散した退職代行運営企業**をスマートヤメマス以外に示す → 「倒産は1件」が崩れる
3. **母集団に入っていない主要サービス**を示す → 母集団の網羅性が崩れる
4. 到達不能とした9件のいずれかが**現在も営業している証拠**を示す → 継続率が変わる

1〜4のいずれも、本調査のデータファイルを直接参照して検証できる形にしてある。
