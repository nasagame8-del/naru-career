# 調査方法（methodology）

対象期間: 2024-01-01 〜 2026-10-07
調査実施日: 2026-10-07
対象: 日本国内向けに提供されていた退職代行サービス

この調査は「退職代行業界は終わった」という結論を作るためのものではない。
NARUの読者（新卒1〜3年目・初めての転職を検討する層）にとって、
「辞める手段が増えたこと」と「次の転職が成功すること」が同じ話なのかを判断するための基礎データを作る。

---

## 1. 母集団の作り方

既存調査（帝国データバンク等）の対象リストを引き写さない。NARU独自の母集団を先に構築し、
外部調査との比較は最後にだけ行う。

入口は4系統。

1. 比較・ランキングサイト（「退職代行 おすすめ」「比較」「一覧」「安い」等）
2. 運営形態別の特集ページ（労働組合運営・弁護士運営）
3. 新規参入の探索（PR TIMES・公式リリース・「提供開始」「サービス開始」）
4. 市場退出イベントの探索（「サービス終了」「破産」「倒産」「廃業」「非弁」）

4系統を別々に収集し、収集元URLを1行ごとに保持したうえで重複除去する。
重複除去は「サービス名の正規化」と「公式ドメイン」の両方で突き合わせる。
サービス名だけの一致では別法人の同名サービスを潰すおそれがあるため、ドメインを優先する。

---

## 2. 情報源の優先順位

| 順位 | source_type | 内容 |
|---|---|---|
| 1 | COURT | 裁判所・官報 |
| 2 | GOVERNMENT / CORPORATE_REGISTRY | 国税庁法人番号公表サイト、gBizINFO |
| 3 | OFFICIAL | 運営企業の公式サイト・特定商取引法に基づく表記・公式告知 |
| 4 | TSR | 東京商工リサーチ |
| 5 | TDB | 帝国データバンク |
| 6 | NEWS | 大手報道 |
| 7 | PR | プレスリリース（PR TIMES等） |
| 8 | OTHER | 比較サイト・まとめサイト等 |

比較サイト・まとめサイトだけを根拠に、倒産・サービス終了を確定しない。
比較サイトは「候補の発見」と「訴求文言の二次確認」にのみ使う。

---

## 3. 各サービスの一次情報の取り方

運営法人・料金・訴求内容は、原則として**公式サイトの「特定商取引法に基づく表記」ページ**を一次情報とする。
このページには運営法人名・代表者名・所在地・料金・返金条件が法定で記載されるため、
比較サイトの記述より信頼できる。

比較サイトの記載と公式の記載が食い違う場合は公式を採り、食い違った事実を `notes` に残す。

---

## 4. 法人番号の特定手順と既知の限界

### 手順

1. 公式の特商法ページから運営法人名と所在地を取得（OFFICIAL）
2. 法人名で検索し法人番号の候補を得る
3. 国税庁法人番号公表サイトの
   `https://www.houjin-bangou.nta.go.jp/henkorireki-johoto.html?selHouzinNo=<13桁>`
   で法人番号・所在地・変更履歴・登記記録の閉鎖有無を確認（CORPORATE_REGISTRY）
4. **特商法ページの所在地と法人番号公表サイトの所在地が一致した場合のみ確定**とする

同名法人は実在する。例として「株式会社アルバトロス」は法人番号の異なる複数法人が存在し、
退職代行モームリの運営法人はそのうち `3020001145095`（神奈川県横浜市中区）である。
名寄せを法人名だけで行うと誤った法人番号を割り当てるため、住所照合を必須とした。

所在地が一致しない、または候補が複数残る場合は `review_required = true` とし、
どちらかを自動的に正解扱いしない。

### 限界（重要）

- 国税庁法人番号公表サイトのWeb-APIはアプリケーションIDの事前申請が必要で、
  発行に2週間〜1か月かかるため**今回は使用していない**。公開ページのGET参照で代替した。
- 同サイトから取得できるのは **`法人番号指定年月日`** であり、**`設立年月日` ではない**。
  法人番号制度の運用開始は2015年10月であるため、2015年以前に設立された法人は
  指定年月日が2015年に揃ってしまう。
  したがって `corporation_established_date` には指定年月日を代入せず、
  別フィールド `corporate_number_assigned_date` として保持する。
  2015年11月以降に指定された法人についてのみ、設立時期の近似値として扱い、その旨を明記する。
- 登記簿上の設立年月日・解散登記は有料の登記情報が必要であり、今回は取得していない。
  「登記記録の閉鎖」は法人番号公表サイトに表示される範囲でのみ判定する。

## 5. 営業状態の判定基準

2026年10月時点の状態を以下に分類する。

| status | 定義 |
|---|---|
| ACTIVE | 公式サイトが正常に表示され、現在も申込または相談ができる状態が確認できる |
| LIKELY_ACTIVE | サイトやSNSは存在するが、申込機能や実営業まで十分確認できない |
| STOPPED | 公式なサービス終了告知がある、または複数の独立した証拠から営業停止が強く推定される |
| BANKRUPT | 破産開始決定・民事再生等を一次性の高い情報で確認 |
| CORPORATE_CLOSED | 法人の閉鎖を公的情報で確認 |
| UNKNOWN | 判断材料不足 |

### BANKRUPT と判定しない事象

次の事象は**単独でも複数組み合わせても BANKRUPT の根拠にしない**。

- HTTP 404
- ドメイン失効
- SNSの更新停止
- LINEが応答しない
- 電話が繋がらない

これらは最大でも STOPPED または UNKNOWN の材料にとどめ、
観測した事実そのもの（例: 「2026-10-07時点でHTTP 404」）を `status_detail` と evidence に残す。

「サービス停止」と「法人の倒産」は別概念として別フィールドで管理する
（`status_2026` と `corporate_status` / `bankruptcy`）。

## 6. 過去との比較

Internet Archive の Wayback Machine Availability API
（`https://archive.org/wayback/available?url=<URL>&timestamp=<YYYYMMDD>`）で
2024年・2025年のスナップショットを特定し、取得できた場合のみ当時の
価格・訴求文言・転職支援の有無を記録する。

スナップショットが存在しない年は NULL とし、「変化なし」とは解釈しない。

---

## 7. 運営形態の扱い

`operator_type` は PRIVATE / LAW_FIRM / LABOR_UNION / OTHER / UNKNOWN の5値。

これとは別に次を独立したフラグとして持つ。混同しない。

- `lawyer_supervised_claim`（弁護士監修と表記している）
- `lawyer_operated`（弁護士法人・法律事務所自身が運営）
- `labor_union_operated`（労働組合自身が運営）
- `labor_union_partnered`（民間企業が労働組合と提携）

「弁護士監修」は運営主体の属性ではなく訴求文言であり、`lawyer_operated` とは別に扱う。
同様に「労働組合と提携」と「労働組合が運営」を同一視しない。

---

## 8. 欠損の扱い

取得できなかった項目は空欄（NULL）のまま保持する。0 や false に変換しない。
`false` は「そのような記載がないことを確認した」場合にのみ用い、
「確認できなかった」場合は空欄とする。この区別を全フィールドで維持する。

---

## 8.5 実行中に判明した方法上の制約

調査を回して初めて分かった制約を記録する。再現時に同じ罠を踏まないため。

### 名寄せはドメイン一致で行ってはいけない

1運営会社が複数ブランドを1ドメインで運営する例がある（`男の退職代行` と `わたしNEXT` はどちらも
to-next.jp）。ドメインで統合すると、読者が選択の対象とする別サービスが1件に潰れる。
サービス名の正規化＋監査可能な別名表（`raw/alias_map.csv`、CONFIRMED / PROVISIONAL / REJECTED）で行う。
ドメインは統合の根拠ではなく、別名判断の証拠として列に残す。

### service_id は出現順で採番してはいけない

名寄せを更新するたび採番が変わり、既に収集したファイルとの突合が壊れる。
`normalized/service_id_registry.csv` でIDを固定し、ファイル間の突合はサービス名で行う。

### 生存確認はサブドメインだけで判定してはいけない

比較サイトはキャンペーン用のLPサブドメイン（`lp.example.jp`）をリンクすることが多い。
LPが畳まれただけで本体が稼働している場合を「消滅」と数えると、市場の縮小を過大に評価する。
名前解決に失敗した場合は本体ドメインへ1回だけフォールバックし、フォールバックした事実を列に記録する。

### Wayback の availability API の回答は安定しない

同一URLに対する回答が連続実行で変動した（2024年分の取得件数が 19 → 15 → 18 → 26 と動いた）。
したがって `status_2024` / `status_2025` は**APIがスナップショットを持つと答えたか**ではなく、
**実際に取得して本文を読めたか**で判定する。

また深い階層のURLで照会するとスナップショットなしが多発する。サイトルートで照会する。

### アーカイブの観測範囲を確認する

保存されていたのが退職代行のLPではなく事務所トップページである場合がある（11件）。
この場合の「訴求に変化なし」は観測範囲の制約であり、変化の不在ではない。
`raw/archive_scope_notes.csv` に記録し、価格比較から除外する。

### 属性別の継続率は生存バイアスで成立しない

運営形態・料金・機能はサイトが到達可能な間しか読めないため、属性が判明したサービスは
定義上すべて継続側に入る。この状態で運営形態別の継続率を出すと全型100%になる。
これは発見ではなく算術の帰結である。

緩和策としてアーカイブから最終観測価格を復元したが（`price_last_observed`）、
非継続側で価格帯が判明するのは1件にとどまり交絡は解消しなかった。
したがって仮説H2・H3・H6は**検証不能**と判定する。検証不能を「支持されなかった」と書かない。

---

## 9. 記録しない／やらないこと

- 推測による穴埋め
- 「安いから潰れた」等の因果の断定（観測されるのは相関まで）
- 仮説に合わない結果の削除
- 既存調査の数字に自社集計を合わせること
