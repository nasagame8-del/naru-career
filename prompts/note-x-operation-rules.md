# note × X 運用ルール

note記事の公開後のX告知、およびnote読者とのエンゲージメント運用のルール。

---

## X告知ルール

- note記事を公開したら、**30分以内**にXで告知する
  - 初速を確保し、noteの「おすすめ」掲載アルゴリズムに乗りやすくするため
- 告知ツイートには、記事の核心・フックとなる**具体的な情報（数字・意外性のある一言）**を含める
  - 単なる「投稿しました」＋リンクだけの告知にしない

---

## スキ読者への選択的フォロバックルール

- 記事にスキをつけてくれた読者は、最もエンゲージメントの高い層として**選択的にフォロバック**する
- **無差別フォローはしない**
  - 過去に「無差別フォローはペナルティリスク・低エンゲージメント」という判断で不採用にした方針を維持

---

## 記事末尾のフォロー誘導

- **次回予告は原則入れない。**
- 「明日は○○を書きます」など、次の記事内容や公開日を約束する文言は禁止。
- フォロー誘導を入れる場合も、本文の余韻を壊さない短い一文に留める。
- フォロー誘導自体も必須ではない。

---

## note画像の簡易運用ルール

noteは画像制作を重くしすぎない。標準は**1記事2枚まで**。

1. **見出し画像 1枚**
   - 1280×670pxを基本
   - タイトル文字は画像内に入れない
   - NARUのティーグリーン #1F6F66、アンバー #B5691B、背景 #FBF8F3 を基調
   - 上質な手描き風フラット、要素を少なく、実在ロゴ・透かしなし

2. **本文画像 0〜1枚**
   - 1200×675pxを基本
   - 記事の核心を1場面だけ視覚化する
   - 長文や複雑な図解は作らない
   - 「文章の休憩」と「内容理解の補助」が目的
   - なくても記事が成立する場合は無理に作らない

下書きでは、本文画像を入れる位置に以下の形式で指示を残してよい。

```
<!-- NOTE_IMAGE: body-01 | 画像の内容を一文で -->
```

公開時に画像が用意できたら、その位置へ差し込む。画像が未生成でも本文制作は止めない。

## タイトルパターン集

note記事のタイトルに使えるフック型の一覧。全記事に**数字・意外性・ギャップ**のいずれかを含めるルール（controversial-post-rules.md）は維持しつつ、以下のパターンを引き出しとして活用する。

### パターン1：数字・意外性・ギャップ型（基本、全記事必須）

- controversial-post-rules.md の「タイトルのフック要素」参照
- 例：「入社3ヶ月で辞めたいと思うのは異常なのか」「何度も消しては書き直した。職務経歴書と向き合っていた頃の話」

### パターン2：「認知的な隙間」型（2026年7月26日追加）

一見つながらない2つの要素（状況＋意外な行動・場所等）を並置し、「なぜ？」という好奇心を意図的に作るタイトル。内容を明かしすぎず、クリックしないと分からない余白を残す。

**型の構造：**
- `[通常予想される行動] ではなく [意外な要素]`
- `[状況] のとき、僕は [意外な場所・行動] にいた/した`

**良い例：**
- 「転職を決める前、僕がやったのは面接対策ではなく『京都』だった」
- 「転職を決めたあの夏、僕は『京都』にいた」

**使用条件（誠実さを保つ制約）：**
1. 「意外な要素」は必ず**実話**であること（experience-notes.mdに記録がある、または本人確認済み）。インパクトのための誇張・捏造はしない
2. タイトルの意味合いの強さは、実際の体験の重みと**釣り合っていること**。息抜き程度の体験を「人生が変わった瞬間」のように過大演出しない
3. 本文冒頭で、タイトルの「意味」を**早めに明かす**（QCEP形式のQ部分で種明かし）。引っ張りすぎて読者が離脱しないようにする
4. 毎回使うものではない。実話の中に「一見つながらない2要素」が実際に存在する場合にのみ使用し、**無理にこじつけない**

**位置づけ：**
- 既存フック（数字・意外性・ギャップ）と併用可能
- 特に**通常回（実体験レポート型）**のタイトルに新しい引き出しとして有効
- 賛否両論型にも使えるが、問いかけ型との組み合わせで使う

## note記事のテーマ・タイトル選定ルール（2026-10-04更新）

### 基本方針

noteの企画は、既存の「4本柱」やカテゴリから機械的に逆算しない。
**NARU自身の実測 → note内の近接競合 → 著者の実体験**の順に判断する。

ピラーは「採用後の整理ラベル」として使い、企画の入口にはしない。

### 1. NARU自身の実測を最優先する

公開済みnoteについて、可能な範囲で以下を集計する。

- インプレッション
- ページビュー
- スキ
- コメント
- 売上
- PV率 = ページビュー / インプレッション
- スキ率 = スキ / ページビュー

判定は次の3軸で行う。

- **露出型**：インプレッションが高い。テーマ自体に需要がある可能性が高い
- **クリック型**：PV率が高い。題材またはタイトルの刺さりが強い
- **反応型**：スキ率・コメント率が高い。読後の共感・保存価値が強い

インプレッション母数が少ない記事のPV率は断定材料にせず、競合調査とセットで使う。

### 2. 次の記事は「伸びた記事の隣の悩み」から作る

候補生成の順序：

1. NARUで反応が良かった記事を1本選ぶ
2. その読者が次に抱えそうな「具体的な悩み・失敗・場面」を3〜10個に分解する
3. note内の近接ジャンルで、同じ悩みが実際にタイトル化・反応されているか確認する
4. experience-notes.md に実体験があるものだけ残す
5. 既存noteと検索意図・エピソードがほぼ同じ候補は除外する

例：
「職務経歴書で何を書けばいいか分からなかった」
→ 接客をどう書き換えたか
→ 調理経験をどう書き換えたか
→ 実績がないとき何を書いたか
→ 面接でその内容をどう説明したか

### 3. 競合調査

候補決定前に、第二新卒・20代転職・未経験IT/Web・職務経歴書・面接・退職などの近接テーマから、
**50〜100タイトルを目安に**確認する。

見るのは文章のコピーではなく、以下の「切り口」。

- 具体的な失敗
- 「思っていたのと違った」という反転
- Before → After
- 年齢・期間・社数など体験を具体化する数字
- 「書けない」「答えられない」「辞められない」など具体的な詰まり
- 1つの出来事をさらに小さな場面に分解した連載

競合タイトルや本文をコピー・近似しない。

### 4. タイトルの必須条件

旧ルールの「数字・意外性・ギャップ」は**必須条件から加点要素へ変更**する。

タイトルは原則、以下を満たす。

1. **誰の・何の悩みかが一目で分かる**
2. タイトルだけで記事テーマの約7割が分かる
3. 著者本人の体験・失敗・戸惑い・変化のどれかが入る
4. 読後に何が分かるか、または「その後どうなった？」が自然に気になる
5. 誇張・釣り・架空の数字を使わない

優先する型：

- 「○○できなかった僕が、△△した話」
- 「○○だと思っていた。でも実際は△△だった」
- 「○○しかしていないと思っていた僕が、△△に変えた」
- 「○社／○ヶ月やって、一番○○だったのは△△」
- 「○○で詰まった僕が、最初に直した△△」

「認知的な隙間」型は補助技法とする。
**何の記事か分からなくなるほど抽象化しない。**

### 5. 類似記事への内部リンク

新規noteに、読者の次の疑問に答える既存記事がある場合は**本文中に1〜2本だけ自然に入れる**。

優先順位：

1. 公開済みの自分のnote記事
2. NARU本体の対応記事
3. 必要な場合のみ一次情報

入れ方：

- 「このとき何を書けばいいかで手が止まった話は、前にも書きました。」
- 「面接での失敗は別の記事で詳しく書いています。」
- 「具体的な構成はNARUの記事にまとめています。」

禁止：

- 文脈と関係ない記事をSEO目的だけで差し込む
- 「関連記事」一覧を大量に置く
- 未公開記事へのリンク
- URLを推測して作る
- 同じリンクを何度も貼る

リンクは必ず公開済みURLを確認してから使用する。

### 6. 採用判定

候補は次の4条件をすべて満たした場合に優先する。

- NARU実測で近い悩みに反応がある
- note競合でも同じ読者心理が確認できる
- 著者本人の実体験がある
- 既存記事と完全重複しない

**「ピラーに合うから書く」ではなく、「読者の反応があり、本人が書けるから書く」。**

## X引用ポスト用文章（2026-10-04追加）

note記事を1本作成するたびに、**Xで引用投稿するための文章も必ず1本セットで作成する**。

### 目的
- noteリンクを貼っただけの告知にしない
- 記事の中で最も刺さる「具体的な悩み・失敗・意外な気づき」をX側で先に提示する
- note本文を読まなくても投稿単体で意味が通るようにする

### 基本形
- 3〜7行程度
- 1行目にフック
- 本文では具体例・数字・Before→Afterのいずれかを入れる
- 最後は「書きました」「まとめました」程度で自然に記事へつなぐ
- ハッシュタグは0〜2個。付けすぎない
- 「投稿しました！」だけは禁止
- 本文の内容と違う煽り、架空の数字、過剰な断定は禁止

### 引用ポスト前提
note側の投稿URLをXで引用する場合、X本文にURLを重ねて入れなくてもよい。
単独ポストとして使う場合のみ末尾にnote URLを追加する。

### 保存
各note下書きとセットで、対応するX投稿文を
`content/note-social/<slug>-x.md`
に保存する。

ユーザーへ記事本文を渡すときは、最後に**「X引用用」**としてコピペできる文章も必ず提示する。
