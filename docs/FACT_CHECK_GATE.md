# NARU Fact Check Gate

Googleの生成AIコンテンツ利用ガイド更新を受け、AI生成・AI補助コンテンツは公開前に人間が事実確認する。

## 対象
本文だけでなく、以下をすべて確認対象とする。

- title
- excerpt / description
- summary
- FAQ
- H2/H3
- 表・箇条書き
- 数値、割合、年次、金額
- 法律、制度、施行日、行政機関の説明
- 「増えている」「最多」「最大級」などの時系列・比較表現
- 転職サービスの料金、求人数、サポート、採用条件
- 著者の一人称経験
- 画像内テキスト、数字、図解内容
- alt

## 3分類
各主張を次のどれかに置く。

1. Fact: 外部で検証できる事実。一次情報を優先して確認する。
2. Experience: 著者本人の実体験。本人が実際に経験した範囲だけを書く。
3. Interpretation: Fact / Experience からの編集上の解釈。事実と混同しない。

## 公開ゲート
1. `node scripts/article-fact-check.mjs --slug <slug>` で確認対象を抽出。
2. BLOCK が1件でもあれば修正する。
3. REVIEW対象を一次情報または著者実体験で確認する。
4. 画像内の文言・数字・altも確認する。
5. PRコメントに確認結果を記録する。
6. 最終Previewを人間が確認し、対象head SHAへ明示的にOKを出す。
7. 表示に関わるコミット後は再確認する。

## 禁止
- AIが自分で「事実確認済み」と宣言して人間確認を代替しない。
- 検索スニペット用のtitle/excerptだけ事実確認を省略しない。
- 古い統計を現在値として扱わない。
- 個人の体験を業界全体へ一般化しない。
- 架空の成功率・年収差・求人件数・実績を作らない。


## CI pre-scan

Article Factory Validation では、記事PRの最新headに対して `npm run article:fact-check -- --slug <slug>` をフルローカルQAの前に実行する。

- `BLOCK` が1件でもあればCIを失敗させ、公開工程へ進めない。
- `REVIEW` はログへ抽出するだけで、自動合格にはしない。
- CI success は Human Fact Check の代替ではない。REVIEW対象は一次情報または著者本人の実体験で人間が確認し、同じhead SHAへ承認を記録する。
- 表示に関わるcommitでhead SHAが変わった場合、古いHuman Fact Check承認を継承しない。


## 読者への付加価値・検索意図の確認（2026-11-07追補）

AIを利用したという理由だけで不合格にしない。一方、一次情報の要約や言い換えを並べただけでは、記事固有の価値を確認できたことにはならない。公開前に次を記事別のFact Check記録へ残す。

1. 対象読者が置かれた具体的な状況と、読後に解決できる問いを一つ記す。
2. 既存記事との役割の違いを確認する。同じ問いに同じ答えを返すページを、キーワードの表記違いだけで増やさない。
3. 記事固有の価値と、その所在（見出し・表・原資料）を記す。確認済みの本人経験、独自に調べた資料の比較、条件による判断手順、読者が使える確認文面などが候補。独自統計や実体験の追加は必須ではなく、未取得なら作らない。
4. 比較表・判断手順・メール例は、公式制度そのものとNARUの編集例を区別する。編集例を公式見解として示さない。
5. 記事数・公開時刻を満たすために、この確認や人間の事実確認を省略しない。

これはNARUの編集基準であり、Googleの合格点・順位保証・公式のチェックリストではない。

## 表示承認と事実確認承認を分ける

- 「見た目に問題なし」「プレビューOK」は表示承認として記録する。その回答だけで本文全体のHuman Fact Checkを完了扱いにしない。
- 人間の事実確認は、確認者、対象head SHA、確認した主張と根拠、未解決事項を記録する。
- 外部制度の検証と著者本人の経験確認を区別する。本人以外が一人称の実体験を推測で承認しない。
- AIによる調査・自動スキャン・CI成功は補助。人間が未確認の項目はPENDINGのままにする。
- リンク追加など限定的な変更では、変更した主張・リンク先との対応を記録し、未変更の本文全体を新たに確認済みと表示しない。

## 更新日と制作説明

- 更新日は、読者への意味のある変更に合わせる。順位の鮮度を装うための日付変更・一括更新を行わない。
- 出典確認日と記事更新日を区別する。リンクの修正だけで、統計・法制度・本文全体を再確認したと扱わない。
- 著者ページのAI利用・人間の確認に関する説明は、実際の工程と一致させる。公開していない審査・資格・監修をあるものとして書かない。
- 根拠不足や重複を発見しても、機械的な全削除・一括noindexは行わない。記事ごとに補強・統合・保持などを検討し、既存の公開承認手順を守る。
